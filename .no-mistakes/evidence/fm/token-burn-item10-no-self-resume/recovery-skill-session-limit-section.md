## Session-limit pause recovery

When reconciling a task whose last status line records `paused: {harness} session usage limit, resets <ts>` (a crewmate hitting its own Claude session usage limit, distinct from account-wide quota exhaustion or a real wedge) and the limit has since reset: if the task's context is past the "warn" band (read via `bin/fm-context-usage.sh` under that task's worktree as `FM_HOME`), relaunch with a carryover note (`bin/fm-control.sh <task-id> relaunch --note "carryover: what is done, what is live, exact pickup commands"`) rather than assuming the existing session will or should continue. Do not simply leave a session-limited pause to clear on its own once the reset time has passed and context is large, because the >1h idle since the stall guarantees the prompt cache has gone cold and a continuing session would pay a full cold re-cache at that session's model rate for no new work. This parallels the existing `bin/fm-returning-session-check.sh` verdict machinery (which bands on context size; the idle-age dimension is what the session-limit case adds), but does not modify that script - this is doc-only guidance for the recovery procedure.
